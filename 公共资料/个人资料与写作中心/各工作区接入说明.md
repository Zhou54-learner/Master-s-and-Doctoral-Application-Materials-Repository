# 各工作区接入说明

## 新路线 / 新 PI 工作区的标准流程

1. **从 main 最新状态开分支。**
2. 先读本中心：事实入口 → 能力边界 → 写作原则 → 相关母版。
3. 进入对应路线工作台，读取 programme / PI 的最新 evidence、eligibility、funding、deadline、contact rules。
4. 选择与该 PI 真正相关的个人叙事资产；没有合适叙事就不要硬套。
5. 起草 PI-specific email / statement / CV emphasis。
6. 做“换名字测试”和事实边界检查。
7. 生成中文审查镜像交本人终读。
8. 只有用户对具体材料明确批准后，才进入路线自己的 `USER_APPROVED / SENT` 流程；默认仍由本人手动发送。
9. 如果本次工作产生了**可跨路线复用的新写作原则或更准确的个人事实**，再单独提炼回 main 的本中心；不要把 PI-specific 内容反向污染母版。

## 工作区可以改什么

可以：
- PI-specific research hook；
- 研究方向强调顺序；
- 是否附 project sheet / statement / papers；
- 邮件长度与 CTA；
- 动态 programme facts。

不应自行改：
- 个人科研 ownership；
- 已核书目信息；
- 核心技能边界；
- 全局发送锁；
- 本中心的长期写作原则。

如确需改变这些共享内容，应先更新 main 的权威源，再让项目分支同步。

## 不要求所有路线统一文风

中心提供底层方法，不要求：
- 所有邮件同样四段；
- 每个 PI 都用 model-choice hook；
- 所有研究陈述都讨论 numerical reliability；
- 所有路线都用同一 CV。

真正统一的是事实边界和写作判断标准，而不是表面模板。
