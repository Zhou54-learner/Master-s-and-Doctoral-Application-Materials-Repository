# 能力边界与禁写项

这些是跨所有路线的硬约束。

## 绝对不能升级的 ownership

- 不写“developed the genetic algorithm from scratch”。
- 不把课题组已有 Python–CST workflow 写成本人独立从零建立。
- 正确核心是：**used / understood / extended / adapted / automated an existing workflow**。
- 不把商业求解器使用经验等同于 FEM / numerical PDE / solver-development research。
- 不把论文署名等同于主导论文或独立提出核心物理结论。

## 未有研究证据时不要写成既有能力

当前不得以“熟练/已做研究”口径声称：
- DFT / VASP / Quantum ESPRESSO
- MD / MLFF
- PyTorch / JAX / GNN / diffusion
- finite-element solver development
- domain decomposition / preconditioning / HPC research
- mature AI4Science research

未来真实完成后再更新事实源。

## AI / Agent 经历的边界

个人曾有学习 Agent / RAG / AI4Science 探索和工程思考，但没有充分研究证据时：
- 不把它写成 ML research；
- 不用“independently developed production AI system”一类夸张口径；
- 若某项目申请确实相关，先回到对应项目/仓库证据重新核验，再决定是否写。

## 阅读与兴趣边界

- 助理读过 PI 论文 ≠ 申请人本人精读过。
- 主页列出的方向 ≠ 申请人已具备该方向方法能力。
- “希望学习 / 想进一步理解”与“已经掌握”必须清楚区分。
- 未来研究方向可以开放，但不能为了 fit 临时编造已经形成的研究经历。

## 本科直申的表达边界

- 可以明确 bachelor-entry 身份，不需要为此道歉。
- 不反复列“我不会什么”；让真实已有项目说明执行能力。
- 也不把本科经历包装成研究生级方法训练。
- 合理姿态：已有一个真实计算研究起点，希望在博士/研究型训练中把方法和物理理解做深。
