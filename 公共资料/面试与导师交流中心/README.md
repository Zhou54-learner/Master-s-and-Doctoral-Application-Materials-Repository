# 面试与导师交流准备中心

更新：2026-09-29｜INTERNAL

这是跨路线共用的**面试 / 导师线上交流 / 预面试准备中心**。它处理的是“已经获得实质性交流意愿之后，如何把已有个人事实组织成可讲、可答、可按导师定制的材料”。它不新增申请路线，也不改变各路线的项目或联系状态。

## 一句话架构

> **本中心：沉淀 70%–80% 可复用的面试母版。**  
> **路线 / PI 工作区：完成 20%–30% 的导师定制、时间安排、具体课题与真实交流记录。**

本中心不替代：
- `公共资料/事实核验/`：个人事实与原始证据的权威源；
- `公共资料/个人资料与写作中心/`：CV、Email、SOP/PS、Research Statement 的写作方法中心；
- 各路线联系记录：回复、会议邀请、时间、结果等真实事件的唯一状态入口。

这四层的边界必须保持单向引用：面试中心读取已核事实和已定稿的写作资产；PI 的课题、名额、会议时间、会议号及会后新事实留在对应路线 / PI 工作区和联系记录，不回写公共个人事实母版。若一项 PI-specific 内容后来被多个工作区复用，先在事实核验层补证据，再提炼为公共资产。

## 什么时候进入这个工作区

只有出现**实质性正向回复**后才启动，例如：
- PI 主动提出腾讯会议 / Zoom / Teams 交流；
- 明确要求准备 PPT、自我介绍、科研汇报或未来方向；
- 要求进一步面试、组会汇报或与组内成员交流。

普通“收到 / 欢迎申请 / 请走系统”不自动触发完整面试准备。

`REPLIED / MEETING REQUESTED` 是联系记录中的组合状态，表示已收到实质性回复并被邀请交流；它不属于 `READY`、`SENT`、`SUBMITTED`、`OFFER` 等申请状态，也不表示正式学校面试、招生承诺或录取。会议日期、时间、时区和会议号未确认时保持“待确认”，不得补填。

## 共用资产

1. [通用PPT与口述母版](通用PPT与口述母版.md)：教育背景、科研轨迹、核心项目、其他经历和开放式未来方向的基础结构；`Why this group` 只提供提问骨架，内容必须按 PI 定制。
2. [科研项目答辩与追问母版](科研项目答辩与追问母版.md)：把每段科研拆成“问题—方法—本人贡献—结果—局限—下一步”，并准备 ownership / 方法 / 可靠性追问。
3. [导师定制覆盖层](导师定制覆盖层.md)：把共用母版映射到某位 PI，控制定制幅度，避免每次从零重做。

后续可在本中心继续沉淀：
- 30 秒 / 2 分钟 / 5 分钟自我介绍；
- 中英文高频问答；
- 通用“未来研究兴趣”母版；
- 反问导师的问题池；
- 面试后复盘模板。

## 推荐工作流

### Phase 0｜记录邀请要求
在对应路线 / PI 工作区记录：
- 对方原话与来源；
- 会议形式；
- 日期 / 时间 / 时区；
- PPT 或语言要求；
- 对方明确要求讲什么。

不要把“交流”自动升级成学校正式面试，也不要自行补不存在的考核要求。

### Phase 1｜建立共用底稿
先从本中心的通用母版抽取稳定内容：
- 个人背景；
- 科研轨迹；
- 本科毕设；
- 两段真实合作科研；
- 技能与能力边界；
- 未来方向的开放式表达。

共用部分通常占 70%–80%。它复用的是已经核实的教育背景、科研轨迹、毕设主线、合作科研、真实 contribution、能力迁移和常见追问；不是把同一套成片 PPT 原样发给所有导师。

### Phase 2｜PI 定制
通常只改：
- 研究连接页；
- 未来方向页；
- 1–2 个强调项目；
- 反问 PI 的问题。

定制部分通常占 20%–30%。至少要有一个来自当轮核验材料的具体研究连接，并根据该 PI 调整科研经历的强调顺序、未来方向落点、特有追问和反问。换导师时不重写事实，也不把相邻经验写成已经掌握的目标技术。

不要因为换导师而改变历史贡献、作者身份、成绩或技能边界。

### Phase 3｜Research Defense
所有写进 PPT 的项目都必须能回答：
- 为什么做；
- 核心物理 / 科学问题是什么；
- 你本人具体做了什么；
- 哪些工作不是你做的；
- 结果说明什么；
- 结果不能说明什么；
- 失败 / 局限 / 下一步是什么。

### Phase 4｜模拟交流
至少做一轮：
- 5–8 分钟连贯陈述；
- 毕设深追问；
- 其他项目贡献追问；
- 未来方向与“为什么这个组”；
- 成绩 / 排名 / 第二学位 / 英语等背景问题；
- 申请人向 PI 的反问。

### Phase 5｜会后复盘
会后在对应路线记录：
- PI 明确说了什么；
- 课题 / 名额 / 学科 / 培养方式的新增事实；
- PI 对申请人的评价或疑问；
- 后续动作与时间点。

把 PI 原话、用户确认与分析判断分开。

### 状态与产物边界

中心文件默认是 `INTERNAL`。路线 / PI 工作区可以建立定制候选，但只有在用户明确需要并完成必要核验后，才生成正式演示文件；会议尚未确认时只保留结构骨架和 TODO，不把它写成正式面试、招生或录取材料。

## 当前使用原则

- 面试内容可以高度复用，但**不是一份 PPT 发给所有导师**。
- 共用部分强调“我做过什么、怎么思考”；定制部分强调“这些能力为什么值得迁移到你的问题”。
- 不为了迎合 PI 把未来方向说死。使用“希望探索 / 愿意学习 / 对……问题感兴趣”，不要假装已经确定博士课题。
- 不假装精读未读论文；如果使用具体 PI 工作作为 hook，必须确认本人准备到可以解释的程度。
- 中文交流时可使用英文图表、术语和页标题；若 PI 未要求英语，不把展示变成额外英语考试。
- PPT 是交流辅助，不是 CV 的逐页朗读。
