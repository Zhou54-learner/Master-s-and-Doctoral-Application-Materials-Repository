本文件只规定上述资产何时可以交接、怎样标注和更新。PI 要求优先于通用展示建议，不把建议页数或论文数量写成老师要求。

## 公共主干交付项

1. 核心项目：证据定位 + ownership 四栏 + 一条输入—本人步骤—输出链 + 已完成/未完成验证。
2. 口述：按通用母版准备短述与深问版本；记录本人是否实际复述、卡在哪一步，不以助手答案代替训练。
3. 技能矩阵：每项已演示证据、迁移条件和待学技术；历史能力、当前新能力分开。
4. 图件：原来源、版本/日期、参数与口径；当前重绘注明处理方法，当前 Demo 不冒充本科图件。
5. 通用 PPT 内容骨架及高频问答：只引用已有母版；最终演示文件在 PI 区制作。

## 最终 PPT / 模拟交流启动条件

不使用“准备七八成”或“读够若干篇”作为完成判据。窗口 4 启动前逐项检查：

| 条件 | 可检查的证据 | 未满足时 |
|---|---|---|
| 个人事实可答 | 核心项目 ownership、工作流和图件有来源；本人能讲出具体步骤 | 保留骨架，先补该项目；无证据的贡献不进主述 |
| 结果边界清楚 | 同模反射/总吸收等口径准确；历史与当前验证分列 | 删除过强结论，公开保留未完成验证，不强迫完成所有研究缺口 |
| 关键概念可解释 | 本人能解释将用于主述的物理/方法，记录口述或操作证据 | 未掌握项只作待学习，不主动当作技能 |
| PI 连接有证据 | 使用的研究判断有论文/官方来源和核验日期；本人能解释主动引用的论文 | 缩小定制范围；无需读完全部论文或掌握全领域 |
| 会议要求与范围明确 | 从唯一联系记录读取排期、平台、PPT/语言要求；选择目标 PI | 未排期时只整理内容骨架与追问，最终材料等安排确认 |
| 本轮确实进入整合任务 | 用户已要求最终整合，且上述条件可检查 | 本 PR 只修架构，不触发制作 PPT/pptx |

完整模拟交流属于窗口 4；此前可做单个项目口述核对。会议已确认不单独构成开始最终制作的充分条件。

## 版本与回写

公共成果在[公共主干落点](README.md)登记来源、版本、状态、已完成/待核与下一步；PI 区记录引用的公共版本及仅修改的强调顺序、研究连接、未来方向和特有问答，不复制 ownership 表作为独立事实源。后续正式产物另存版本，旧版按仓库归档规则保留；已发材料不覆盖。

会后暴露的通用短板回写公共准备；新个人事实先进入事实核验；PI 原话、课题/名额/培养信息留在 PI 区；回复、会议与结果事件只在对应路线联系记录维护。学习笔记和准备完成均不等于发送、提交或录取。
