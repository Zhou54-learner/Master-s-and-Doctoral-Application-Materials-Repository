## 1. 核心规则

1. **同一学校首封之间至少间隔 3 个自然日。**
2. 任一学校在一个 3 天观察周期内，只允许 1 位 PI 进入 `SENT / AWAITING RESPONSE`。
3. 两所学校彼此独立，因此可以同时各有 1 位 PI 处于等待回复状态；这不算同校并发。
4. 后续 PI 的材料可以提前准备、终审并进入 `READY_REVIEW`，但不得提前发送。
5. 即使前一位 PI 在 3 天内提前回复，也默认仍保持最短 3 天首封间隔；除非本人明确要求打破节奏。
6. 第 3 个自然日只做一次状态评估，不自动催信；是否继续下一位由本人决定。
7. follow-up 与新首封分开管理；任何 follow-up 同样需要本人确认。
8. Gmail 连接不构成发送授权；实际投递由本人手动完成。

## 2. 执行模式

### ChatGPT / GPT Work 负责
- 从公共母版抽取稳定事实；
- 对当前 PI 做最新招生/研究方向/邮箱二次核验；
- 根据该 PI 的真实研究方向改写邮件桥梁段；
- 只在必要时做 PI-specific CV 微调；
- 整理最终外发包：邮件正文 + CV + transcript + 必要附件；
- 完成事实、措辞、附件、文件名、收件地址终审；
- 将包升级到 `READY_REVIEW` 并交给本人。

### 本人负责
- 逐封审阅；
- 明确是否批准该 PI；
- 手动投递；
- 将实际发送事实/收到的回复带回仓库或 Chat；
- 决定第 3 天后是否启动下一位。

## 5. 每个 3 天周期的标准动作

### Day 0
- 本人审阅当前 PI 包；
- 本人明确批准后手动发送；
- 仓库记录 `SENT / AWAITING RESPONSE`；
- 同校下一位只进入准备状态，不发送。

### Day 1–2
- 等待回复；
- 可继续准备下一位联系包；
- 若收到回复，优先处理当前 PI 的沟通，不自动触发下一封首封。

### Day 3
- 对当前 PI 做状态评估：
  - 有实质正面回复：进入 `POSITIVE_SIGNAL`，优先处理回复/面试；是否继续下一位由本人决定；
  - 明确无名额：记 `CAPACITY_REJECTION`；可启动下一位，但仍不得早于 3 天最短间隔；
  - 明确不匹配：记 `FIT_REJECTION`；用反馈调整后续文案；
  - 无回复：记录 `AWAITING / Day-3 reviewed`，可在本人确认后启动下一位；不自动 follow-up。

### Day 7–10
- 若仍无回复且该 PI 值得继续：考虑唯一一次 follow-up；
- follow-up 不影响已经按 3 天间隔推进的后续 PI，但同样必须本人批准。

## 6. 包处理原则

每一位 PI 都从公共母版开始，而不是复制上一位邮件后只换名字：

1. 读取公共 CV / transcript / thesis 事实母版；
2. 二次核验 PI 当前研究与招生状态；
3. 找到 1–2 个最真实的桥梁，不追求“完美匹配”；
4. 保留统一的经历主干，定制第三段与具体问题；
5. 审查是否存在过度包装、未经证实的招生结论或不必要的夸赞；
6. 输出单 PI 联系包；
7. 本人审核；
8. 本人手动发送。
