## 2. 与 A 线一致的核心纪律

1. **事实先于文案**：每位 PI 先核招生/组状态/研究桥梁，再写邮件。
2. **公共材料冻结，PI 包只做必要定制**：不为每位导师重写整份经历。
3. **状态唯一维护**：准备材料不等于发送；真实发送/回复事件在本流水线记录。
4. **人工终审**：邮件和附件在升级 READY 前做事实、措辞、收件地址、附件一致性核对。
5. **用户发送锁**：任何邮件必须由用户对该封邮件明确确认“可以发”后才能发送。Gmail 连接不等于授权。
6. **本人手动投递**：当前 C 线默认由本人完成实际发送，ChatGPT / GPT Work 不代发。
7. **不补写不存在的事实**：不夸大 GA、AI4Science、DFT/ML；不把组扩张 proxy 写成“容易录”。
8. **真实回复优先更新判断**：网页 proxy 的 P0/P1/S/E 可被回复/面试结果覆盖。
9. **同校串行**：同一学校两封首封之间至少间隔 3 个自然日；任一 3 天周期只保留 1 位该校 PI 作为当前首封等待对象。

## 4. 流水线方式

### 4.1 准备
- 可以提前准备后续 PI，但**发送仍按学校分别串行**。
- 公共英文 CV / transcript 基线复用；只有确有必要才做 PI-specific CV。
- 每位 PI 轮到发送前，都要重新核一次最新招生/研究信息；已有草稿不能机械直接发送。
- 首封核心结构：申请目标 → 已完成研究能力 → 与该组的真实桥梁 + 一个明确问题。
- 首封默认附件：英文 CV + 本科成绩单；论文全文除 PI 明确要求外不默认堆附件。

### 4.2 发送
- HKUST(GZ) 与 CUHK-Shenzhen **两条队列彼此独立**，可同时各有 1 位 PI 等待回复。
- **同一学校两封首封之间至少间隔 3 个自然日。**
- 即使上一位提前回复，也默认不突破这个最短间隔，除非本人明确要求改变节奏。
- 每封都必须用户逐封审核、明确批准，并由本人手动投递。
- 不同学校/组之间不提其他申请对象，不制造排他性承诺。

### 4.3 等待与复评
- 发送后第 3 个自然日：做状态评估，不自动催信。
- Day 3 无回复：本人可决定是否推进同校下一位；上一位仍可继续等待。
- 7–10 天无回复：结合招聘页、优先级与新增信息决定是否 follow-up 1 次。
- follow-up 仍需用户确认；原则上最多 1 次。
- 明确无名额后归 `CAPACITY_REJECTION`；明确不匹配归 `FIT_REJECTION`。

## 6. 单 PI 联系包标准

每次只把**当前轮到的 PI**升级为完整联系包：

1. 最新 PI / group / recruitment 核验；
2. 收件邮箱核验；
3. 研究桥梁说明；
4. 针对性首封正文；
5. 公共英文 CV（必要时最小定制）；
6. 最新正式 transcript；
7. PI 页面明确要求时再增加论文/项目页；
8. 发送前事实与附件终审；
9. 升级 `READY_REVIEW`；
10. 用户审阅并明确批准后，升级 `USER_APPROVED`；
11. 本人手动发送并回填实际事件。
