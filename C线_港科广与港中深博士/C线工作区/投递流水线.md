## 2. 核心纪律

1. **事实先于文案**：轮到某位 PI 时重新核招生、研究方向、项目入口和邮箱。
2. **公共母版稳定，PI 包只做必要定制**：研究经历事实不随导师改写。
3. **双校独立串行**：HKUST(GZ) 与 CUHK-Shenzhen 各自只保留 1 位当前首封等待对象。
4. **同校最短 3 天间隔**：同一学校两封首封之间至少间隔 3 个自然日。
5. **材料可以提前准备，发送不能提前**：下一位可做到 READY_REVIEW，但不得越过同校 3 天节奏。
6. **人工终审**：邮件、收件邮箱、CV、transcript、附件清单全部核过后才可 READY_REVIEW。
7. **用户发送锁**：READY_REVIEW 不等于授权；只有用户对具体 PI 明确批准，才可 USER_APPROVED。
8. **本人手动投递**：当前 C 线实际发送全部由用户本人操作，ChatGPT / GPT Work 不代发。
9. **真实回复优先**：网页 proxy 会被 PI 的有名额 / 无名额 / 面试 / fit feedback 覆盖。
10. **不伪造排他性**：节奏控制用于保证定制质量、降低同校高频并发，不向 PI 虚构“只申请您一位”。

## 4. 单 PI 标准流程

1. 从公共 CV / transcript / thesis 事实母版读取稳定信息；
2. 二次核验 PI 当前身份、组主页、研究方向、招生/扩组信号、学校邮箱；
3. 二次核验对应正式 PhD programme 的 bachelor-entry、deadline、funding/English 等边界；
4. 找 1–2 个真实研究桥梁；
5. 写针对性首封，不做“换名字模板”；
6. 只在必要时做 PI-specific CV 微调；
7. 确定首封附件；
8. 做事实、措辞、文件名、收件地址、附件一致性终审；
9. 升 `READY_REVIEW`；
10. 用户逐封终读；
11. 用户明确批准后升 `USER_APPROVED`；
12. 用户本人手动发送；
13. 回填真实发送日、正文版本、附件、回复；
14. 同校 Day 3 状态评估后决定是否推进下一位。

## 5. 等待与复评

- **Day 0**：用户批准并手动发送；状态 `SENT / AWAITING RESPONSE`。
- **Day 1–2**：等待；可准备下一位，但同校不得发送。
- **Day 3**：做状态评估，不自动催信。
  - 正面回复：优先处理当前 PI；是否继续下一位由用户决定。
  - 明确无名额：`CAPACITY_REJECTION`。
  - 明确不匹配：`FIT_REJECTION`，用反馈修订后续策略。
  - 无回复：记录 Day-3 reviewed；用户可批准同校下一位。
- **Day 7–10**：若仍无回复且值得继续，可考虑唯一一次 follow-up；仍需用户批准。
